# httplogs

## Internal Telemetry

The following telemetry is emitted by this component.

### otelcol_httplogs_receiver.filetracking.errors_total

The total number of checkpoint store operations that failed while processing a tracked file delivery.

Only produced when file_tracking.enabled is true. A non-zero "op=save, on_error=degrade" value means checkpoints are being dropped mid-delivery. That is expected with on_error=degrade (continued untracked, at-least-once preserved), but should be investigated in scaled deployments.

| Unit | Metric Type | Value Type | Monotonic | Stability |
| ---- | ----------- | ---------- | --------- | --------- |
| 1 | Sum | Int | true | Development |

#### Attributes

| Name | Description | Values | Semantic Convention |
| ---- | ----------- | ------ | ------------------- |
| backend | The checkpoint store backend in use. | Str: ``inmem``, ``storage`` | - |
| on_error | The on_error policy in effect for the failed store operation. | Str: ``degrade``, ``fail`` | - |
| op | The checkpoint store operation that failed. | Str: ``load``, ``save`` | - |

### otelcol_httplogs_receiver.filetracking.line_attr_batches_skipped_total

The total number of log batches forwarded without the file.line attribute because their record count did not match the number of source lines decoded.

Only produced when file_tracking.enabled is true and the signal is logs. Non-zero in steady state means the configured encoding is not 1 line to 1 record for this receiver. The affected batches are still forwarded (with the file line attribute absent), and file tracking checkpointing is unaffected.

| Unit | Metric Type | Value Type | Monotonic | Stability |
| ---- | ----------- | ---------- | --------- | --------- |
| 1 | Sum | Int | true | Development |

### otelcol_httplogs_receiver.filetracking.resumed_files_total

The total number of file deliveries processed with file tracking, by outcome (fresh file, resumed from a checkpoint, or stale checkpoint).

Only produced when file_tracking.enabled is true and the delivery carries a tracked file name. A non-zero "stale" result means resent files end before their recorded checkpoint (shrunk, truncated, or a different file reusing the name).

| Unit | Metric Type | Value Type | Monotonic | Stability |
| ---- | ----------- | ---------- | --------- | --------- |
| 1 | Sum | Int | true | Development |

#### Attributes

| Name | Description | Values | Semantic Convention |
| ---- | ----------- | ------ | ------------------- |
| result | Outcome of a tracked file delivery. | Str: ``fresh``, ``resumed``, ``stale`` | - |

### otelcol_httplogs_receiver.filetracking.skipped_lines_total

The total number of already-exported file lines skipped while resuming a tracked file delivery.

Only produced when file_tracking.enabled is true and the delivery carries a tracked file name with an existing checkpoint. Each resumed delivery is counted for the lines of its file it skips.

| Unit | Metric Type | Value Type | Monotonic | Stability |
| ---- | ----------- | ---------- | --------- | --------- |
| 1 | Sum | Int | true | Development |

### otelcol_httplogs_receiver.filetracking.tracked_files

The number of files currently tracked by the in-memory checkpoint store.

Only produced when file_tracking.enabled is true and no storage extension is configured (the in-memory backend only). It is the capacity signal against max_tracked_files.

| Unit | Metric Type | Value Type | Stability |
| ---- | ----------- | ---------- | --------- |
| 1 | Gauge | Int | Development |
